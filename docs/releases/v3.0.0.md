# Job Monitor v3.0.0

React, Primer, TypeScript and the table library each moved a major version. Nothing about what the app
*does* has changed: it is a major version because the user interface was rewritten to get there, not
because the product was redesigned. Two features arrive with it, and one dependency did **not** move —
read that part before installing if you use the tray on Cinnamon.

## Long-lived feature branches get a tab

Branches shared between your fork and the upstream were invisible here: both ends of their pull requests
live in the upstream, so the Pull requests tab's fork-head filter excluded them. The new tab answers *why
is this sitting there* — a stage strip per pull request (opened → checks → mergeable → auto-merge armed →
merged) naming what it is stuck on, and how far behind the default branch each branch is (`47 commits
behind 2026.1`).

Three actions, and **none of them merges**: bring the default branch in, pull the upstream's copy down
into your fork, offer your fork's work back upstream. Each opens a pull request and arms auto-merge;
GitHub does the merging when the checks pass. Bringing the default branch in goes through a
`sync/main-into-<branch>` branch pinned to one commit, matching the `create-merge.yml` workflow these
repositories already use. On the desktop, Claude drafts the offered pull request's title and description
for you to edit.

On by default; switch it off under **Settings → PR automation**.

## The auto-rerun engine says what it decided

It used to work out a precise reason for every run it passed over and throw it away, so a pull request
that had quietly stopped being retried looked exactly like one with nothing to do — three real bugs were
hiding in that silence, and all three are fixed. Every decision is now recorded, **including the
decisions not to act**, and readable in a **Diagnostics** tab that follows the log live, searchable down
to a run id or a failure fingerprint. Pull requests also gain an **arm auto-merge** button, an
`auto-merge` badge naming the strategy and who armed it, and a `re-run ×3` badge carrying every attempt.

## Two fixes worth naming

**A flow reports its last result, not what it is doing now.** A group could read pending while everything
in it had finished, and could show fewer verdicts than it had flows — both from treating a list of runs as
one thing. A flow now reports its last *finished* run in every tab, with a spinner beside the badge for a
run in flight.

**Getting from a failing job to the failure.** The button that opens a failing check or job in the
Failures tab was hidden unless the AI integration was on — wrong about the tab, since the coloured log,
the annotations and the copyable report are all there without a model. It now appears whenever the failure
is in that tab.

## Under the hood

| | before | now |
|---|---|---|
| React | 18.3 | 19.2 |
| Primer | 36.27 | 38.35 |
| TypeScript | 6.0 | 7.0 |
| TanStack Table | 8.21 | 9.1 |
| styled-components | 5.3 | *removed* |
| Electron | 42.5 | 42.8 — **not** 43 |

Primer 38 removes the `sx` prop, `Box` and `Octicon`, and Primer 36 requires React 18 exactly — so React
19 was unreachable without moving the styling layer in one change: **804 `sx` props, 402 `Box` elements
and 53 `Octicon` elements across 41 files**, now 43 CSS modules. Styles are a cacheable stylesheet rather
than CSS generated at startup, and three mouse-only badges became keyboard-reachable — Primer 38 refuses
to attach a tooltip to something you cannot focus.

**Electron stays on 42.** 43 was upgraded to and reverted: Chromium 150 rewrote its StatusNotifierItem
implementation, and on Cinnamon the result is a tray icon rendered as the icon theme's missing-image
placeholder **and a tray menu that does not open at all** — the whole interface of an app whose window is
hidden. The icon file is not involved: the previous icon reproduces it exactly under 43. The cost is a
quarter of Chromium's security fixes, which is why it is written down rather than quietly pinned.

## Upgrading

No migration needed: new settings fill in with defaults, existing configuration is read unchanged, and
both new features can be switched off under Settings. Token requirements are unchanged — the AI features
need the desktop app and the [`claude`](https://docs.claude.com/en/docs/claude-code/overview) CLI, the
writes need a classic token with the `repo` scope on a repository you can write to.

Installers are attached for macOS (arm64 `.dmg` / `.zip`), Windows (`setup.exe`) and Linux (`.AppImage`,
`.deb`). Existing desktop installs pick this up via auto-update.
